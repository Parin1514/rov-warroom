# RoV War Room

เว็บ React สำหรับวางแผนทีม RoV ห้าคน ดราฟต์ฝั่งเราและคู่แข่ง บันทึกฮีโร่ถนัด ดูสถิติ และจับเวลาเป้าหมายโดยให้โค้ชกดบันทึก

## เปิดบนเครื่อง

ต้องใช้ Node.js 22 หรือใหม่กว่า

```sh
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดง โหมดซ้อมไม่ต้องมีบัญชีและเก็บข้อมูลในเบราว์เซอร์นั้น หรือรัน `npm run build` เพื่อสร้าง `dist/` ฟังก์ชัน `/api/meta` และ `/api/analyze` ใช้บน Vercel หรือ `vercel dev`

## การดราฟต์

เลือกช่องของทีมเราหรือคู่แข่งเพื่อเปิดคลังตามเลน ตัวถนัดจากโปรไฟล์ทีมเราแสดงก่อนรายการในเลนและอาจเป็นฮีโร่จากเลนอื่น กด **ดูทุกเลน** เพื่อขยายรายการ บนมือถือคลังและหน้าตรวจคำแนะนำเปิดจากด้านล่างโดยระบุฝั่งและเลนไว้ด้านบน

กดฮีโร่เพื่อดูคู่เล่น ความเสี่ยง และตัวที่ยังแบนได้ก่อน ระบบยังไม่เปลี่ยนดราฟต์จนกด **ยืนยันเลือก**, **ยืนยันเปลี่ยนตัว** หรือ **ยืนยันแบน** สถิติอัตราแบนจากแรงก์แยกจากคำแนะนำตัวแก้ทาง

ใช้ปุ่ม **ลดการเคลื่อนไหว** ที่แบนเนอร์เพื่อหยุดฉากเคลื่อนไหว การเลื่อนของภาพฮีโร่ และวงเตือนบนแผนที่ ระบบเคารพการตั้งค่าลดการเคลื่อนไหวของอุปกรณ์ด้วย สัญญาณใกล้เกิดใหม่เริ่มที่ 15 วินาทีก่อนเวลาที่บันทึกไว้และยังแสดงข้อความเมื่อปิดแอนิเมชัน

## รายละเอียดฮีโร่และบิลด์

กดไอคอนรูปหนังสือที่การ์ดฮีโร่ หรือกด **รายละเอียดฮีโร่และบิลด์** ในแผงวิเคราะห์ รายละเอียดมีสกิล สถิติแรงก์ไทย ชุดไอเทม รูน พลังแฝง และสกิลชาเลนเจอร์ตามข้อมูลที่ยืนยันได้ มีลิงก์อ้างอิงและปุ่มคัดลอกชุดเป็นข้อความ ไม่ได้ส่งข้อมูลเข้าเกม

สถิติชนะ/เลือก/แบนเป็นของฮีโร่ในแรงก์ ไม่ใช่ของบิลด์ ชุดตั้งต้นอิงหน้า Garena รายตัวและไม่มีวันแพตช์ที่ยืนยันสำหรับชุดนั้น ไอเทมตามสถานการณ์แสดงเป็นตัวเลือกตามบทบาท สกิลอิงชื่อและข้อมูลจาก RoVGuide หรือ Garena หากไม่มีลำดับอัปที่ยืนยันได้ ระบบแสดงสกิลตามช่องในเกมแทน

Hover ใช้แสงกวาด ขอบ และภาพขยายเฉพาะจุด มือถือใช้การกดและสถานะเลือกแทน ปุ่มลดการเคลื่อนไหวครอบคลุมหน้ารายละเอียดและเอฟเฟกต์ Hover

## เปิดห้องออนไลน์บน Vercel

1. สร้าง Supabase โปรเจกต์ใหม่สำหรับแอปนี้ แนะนำ Singapore สำหรับทีมในไทย จากนั้นรัน `supabase/migrations/202611130001_war_room.sql` ด้วย Supabase CLI หรือ SQL Editor
2. เปิด Email Auth แล้วตั้ง Site URL และ Redirect URLs เป็นโดเมนของเว็บ เช่น `https://<ชื่อโปรเจกต์>.vercel.app` ตามสภาพแวดล้อมที่ใช้จริง ตั้ง SMTP ของทีมเมื่อจะส่งลิงก์ให้ผู้เล่นจริง และตรวจว่าเทมเพลต magic link มีลิงก์ยืนยัน
3. สร้างโปรเจกต์ Vercel จากโฟลเดอร์นี้โดยเลือก Vite ตั้ง `VITE_SUPABASE_URL` และ `VITE_SUPABASE_PUBLISHABLE_KEY` ตาม `.env.example` แล้ว deploy ใหม่ ค่าคีย์นี้ต้องเป็น publishable key ไม่ใช่ service role key
4. โค้ชกด **ห้องออนไลน์** และลงชื่อด้วยอีเมล จากนั้นสร้างห้อง เปิดแท็บ **ผู้เล่น** เพื่อสร้างลิงก์แยกให้แต่ละช่อง ผู้รับต้องลงชื่อและกดรับคำเชิญ ลิงก์ใช้ได้ครั้งเดียวและหมดอายุใน 7 วัน
5. โค้ชจัดดราฟต์ แบน นำเข้าเมต้า และกดจับเวลา ผู้เล่นเห็นข้อมูลร่วมกันและแก้โปรไฟล์ในช่องที่ตนรับเชิญ กลับมาเปิด URL ห้องเดิมเพื่อทำงานต่อ ไม่ต้องส่งลิงก์รับสิทธิ์ซ้ำ

โหมดซ้อมเป็นข้อมูลคนละชุดกับห้องออนไลน์ ดราฟต์โหมดซ้อมไม่ได้ถูกส่งเข้าฐานข้อมูลตอนสร้างห้อง หากทีมเปิดหลายอุปกรณ์ให้ตรวจว่าเห็นสถานะ **ซิงก์สด** และลองแก้ดราฟต์บนเครื่องโค้ชก่อนเริ่มซ้อม ระบบดึงข้อมูลซ้ำเป็นช่วง ๆ หากพลาดการแจ้งเตือน

## เมต้าและ 9Router

- ข้อมูลตั้งต้นจาก [RoVGuide](https://rovguide.com/th/heroes) และ [สถิติแรงก์ไทย](https://rovguide.com/th/meta) ณ 19 ต.ค. 2569 มี 130 รายการ รวม Flowborn สองร่างแยกกัน ระบบตั้งให้ดราฟต์สองร่างพร้อมกันไม่ได้เพื่อกันเลือกซ้ำในโหมดซ้อม ให้ยืนยันกับกติกาแมตช์ก่อนใช้จริง
- ปุ่ม **ตรวจสถิติใหม่** อ่านตารางแรงก์จากแหล่งเดิมผ่านฟังก์ชันฝั่ง Vercel และบอกวันที่ของข้อมูลที่ต้นทางเผยแพร่ หากต้นทางเปลี่ยนหน้าเว็บหรือยังไม่มีสถิติใหม่ ให้เก็บชุดเดิมหรือนำเข้า JSON จากแหล่งที่เชื่อถือได้
- [แพตช์อ้างอิง 4 พ.ย. 2569](https://www.rov.in.th/patch-notes/hotfix261104) และ [ประกาศล่วงหน้า 17 พ.ย. 2569](https://www.rov.in.th/patch-notes/hotfix261117) แสดงแยกจากวันที่สถิติ
- คำแนะนำคู่เล่นและแบนใช้กฎใน `src/domain.mjs` ไม่ใช่สถิติแพ้ทางรายคู่ และจะไม่บอกให้แบนฮีโร่ที่ถูกเลือกไปแล้ว
- หากต้องการใช้ [9Router](https://github.com/decolua/9router/blob/master/gitbook/content/en/integration/other-tools.md) ตั้ง `NINE_ROUTER_BASE_URL` (ลงท้าย `/v1`), `NINE_ROUTER_API_KEY` และ `NINE_ROUTER_MODEL` บน Vercel โดยไม่ใส่คำนำหน้า `VITE_` ใช้ HTTPS ที่เซิร์ฟเวอร์ Vercel เข้าถึงได้ ส่วน `localhost` ใช้ได้เฉพาะการรันในเครื่องที่ 9Router กำลังทำงาน ไม่ใช่ Vercel production
- 9Router รับรหัสฮีโร่ ดราฟต์ แบน และข้อมูลสถิติอ้างอิง ไม่ส่งชื่อผู้เล่น อีเมล หรือโน้ตทีม ไม่ได้ดึงเทเลเมทรีจากเกม และหากเชื่อมไม่ได้ กระดานยังวิเคราะห์ด้วยกฎในตัวได้

## ตัวจับเวลา

โค้ชกด **เริ่มแมตช์** พร้อมนาฬิกาเกม แล้วกดจุดบนแผนที่หรือ **บันทึกฆ่า** เมื่อเห็นการสังหาร กดย้อนรายการได้ถ้ากดผิด ตั้งค่าเวลาเกิดใหม่ของแต่ละจุดก่อนใช้ มอนสเตอร์ตำนานตั้งต้น 180 วินาที ตาม [Beta 55 ของ Garena](https://www.rov.in.th/patch-notes/beta55) และสลับตัวจับเวลาบ่อมังกรหลังนาที 15 แผนที่เป็นภาพอ้างอิง ไม่ใช่ภาพสด ควรเปิดตั้งเวลาอัตโนมัติในระบบของอุปกรณ์ที่ใช้ และใช้ระหว่างแข่งเมื่อกติกาผู้จัดอนุญาตเท่านั้น

## ทดสอบและเครดิต

- `npm test` ตรวจตรรกะดราฟต์ คู่เล่น แบน ตัวจับเวลา และนำเข้าข้อมูล
- `scripts/smoke.cjs` ตรวจ UI ด้วย Playwright และ Chromium ต้องเปิดเว็บทดสอบก่อน แล้วกำหนด `SMOKE_URL` หากไม่ใช่ URL เริ่มต้น
- `scripts/sql-smoke.mjs` รัน migration ใน PostgreSQL/PGlite พร้อมทดสอบสิทธิ์ด้วยบัญชีจำลอง ต้องติดตั้ง PGlite แยกสำหรับงานทดสอบ
- ภาพ Abyssal Rift มาจากประกาศ Beta 55 ของ Garena และภาพฮีโร่มาจาก Garena หรือ RoVGuide ตาม URL ใน `src/heroes.json` เป็นเครื่องมือชุมชน ไม่ใช่บริการทางการของ Garena หรือ Tencent
